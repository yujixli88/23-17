# The Last Chime

`Our project` — небольшой full-stack проект с детективным браузерным квестом «Последний звонок в 23:17». Пользователь регистрируется или входит в аккаунт, исследует сцену преступления, собирает улики, решает две загадки и обвиняет одного из подозреваемых. Прогресс сохраняется в SQLite, поэтому расследование можно продолжить позже.

## Как устроен проект

```text
Браузер
  └─ game.html + game.css + game.js
       │ HTTP/JSON API
       ▼
FastAPI (main.py)
  ├─ auth.py        пользователи, сессии и прогресс
  └─ game_logic.py  сюжет, улики, загадки и проверка обвинения
       │
       ▼
  data/game.sqlite3

Администратор
  └─ admin_app.py (PySide6)
       └─ читает и изменяет ту же SQLite-базу
```

## Как работает веб-часть

1. `main.py` запускает FastAPI и отдаёт [`game.html`](./game.html), [`game.css`](./game.css) и [`game.js`](./game.js).
2. При открытии страницы JavaScript вызывает `/api/auth/me` и проверяет, есть ли действующая сессия.
3. Если пользователь не вошёл, интерфейс показывает регистрацию или вход. При регистрации проверяются имя, email, пароль длиной от 12 до 128 символов и уровень английского `A1`–`C2`.
4. После успешной регистрации или входа сервер создаёт подписанную cookie-сессию и CSRF-токен. Cookie помечена как `HttpOnly`, а изменяющие состояние запросы требуют заголовок `X-CSRF-Token`.
5. Клиент получает данные расследования через `/api/game`: описание дела, подозреваемых, улики и текущий прогресс.
6. Нажатие на объект сцены отправляет `/api/game/clues/{clue_id}`. Сервер проверяет идентификатор и добавляет улику в `game_progress`.
7. После изучения дела игрок проходит две загадки через `/api/game/challenge` и `/api/game/answer`. Верный ответ увеличивает `stage`.
8. Обвинение разрешено только после двух решённых загадок. `/api/accuse/{suspect_id}` проверяет подозреваемого; правильный ответ отмечает игру завершённой.
9. Кнопка перезапуска очищает улики, возвращает `stage` к `0` и снимает флаг завершения.

## Основные API-маршруты

### Авторизация

| Метод и путь | Что делает |
| --- | --- |
| `GET /api/auth/email-availability` | Проверяет формат и доступность email. |
| `POST /api/auth/register` | Создаёт пользователя и сразу авторизует его. |
| `POST /api/auth/login` | Проверяет email и пароль, применяет ограничение неудачных попыток. |
| `GET /api/auth/me` | Возвращает текущего пользователя и CSRF-токен. |
| `POST /api/auth/logout` | Удаляет сессию и cookie. |

### Игра

| Метод и путь | Что делает |
| --- | --- |
| `GET /api/game` | Возвращает данные квеста и прогресс пользователя. |
| `POST /api/game/restart` | Сбрасывает прогресс. |
| `POST /api/game/clues/{clue_id}` | Сохраняет найденную улику. |
| `GET /api/game/challenge` | Возвращает загадку текущего этапа. |
| `POST /api/game/answer` | Проверяет ответ и при успехе переводит игрока на следующий этап. |
| `POST /api/accuse/{suspect_id}` | Проверяет финальное обвинение и завершает игру при правильном выборе. |

Защищённые маршруты требуют действующей сессии. POST-маршруты, изменяющие данные, дополнительно требуют CSRF-заголовок.

## Данные и безопасность

В SQLite создаются три основные таблицы:

- `users` — имя, email, уровень английского, хеш и соль пароля, время активности и статус блокировки;
- `sessions` — хеш идентификатора сессии, пользователь, CSRF-токен и срок действия;
- `game_progress` — этап расследования, JSON-массив найденных улик и признак завершения.

Пароли пользователей не хранятся в открытом виде: используется `PBKDF2-HMAC-SHA256` с солью и 600 000 итерациями. Сессии подписываются HMAC-SHA256, а при пяти неудачных попытках входа с одного IP включается ограничение на 15 минут.

Для production рекомендуется задавать секрет сессии через переменную окружения `GAME_SESSION_SECRET` длиной не менее 32 байт. Если переменная не задана, приложение создаёт локальный ключ в `~/.last_chime/session.key`.

## Запуск

Нужен Python 3.10+ с доступом к установке зависимостей.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload
```

После запуска откройте <http://127.0.0.1:8000/>.

Путь к базе можно изменить:

```powershell
$env:GAME_DATABASE_PATH = "C:\path\to\game.sqlite3"
$env:GAME_SESSION_SECRET = "минимум-32-байта-секрета-для-сессий"
python -m uvicorn main:app --reload
```

## Админ-панель

Админка запускается отдельно и использует ту же базу:

```powershell
$env:GAME_ADMIN_PASSWORD = "длинный-пароль-администратора"
python admin_app.py
```

Если `GAME_ADMIN_PASSWORD` короче 10 символов, приложение не допускает вход. При первом запуске с коротким или отсутствующим паролем интерфейс показывает подсказку задать пароль через переменную окружения. После входа доступны:

- фильтрация пользователей по имени и email;
- просмотр уровня английского, дат регистрации и последней активности;
- просмотр этапа игры и статуса завершения;
- блокировка и разблокировка аккаунта;
- сброс прогресса;
- окончательное удаление аккаунта.

Таблица обновляется автоматически каждые 30 секунд. Пароли пользователей админ-панель не читает и не показывает.

## Тесты

Запуск тестов из корня проекта:

```powershell
python -m unittest discover -s tests -p "test_*.py"
```

Тесты создают временную SQLite-базу, поэтому рабочие данные из [`data/game.sqlite3`](./data/game.sqlite3) не изменяются. Проверяются загрузка фронтенда, регистрация и нормализация email, хеширование пароля, вход, защищённые маршруты, CSRF, сохранение и сброс прогресса, миграция старой схемы и получение пользователей админ-панелью.

## Замечания по сопровождению

- Сюжет и правила квеста меняются в [`game_logic.py`](./game_logic.py); интерфейс не должен дублировать серверную проверку ответов.
- Изменения структуры SQLite следует добавлять в `initialize_database()` в [`auth.py`](./auth.py), чтобы существующие базы могли автоматически обновиться.
- Изменения API нужно синхронно отражать в [`main.py`](./main.py) и [`game.js`](./game.js), а затем покрывать тестами в [`tests/test_game_auth.py`](./tests/test_game_auth.py).
- [`data/game.sqlite3`](./data/game.sqlite3) содержит пользовательские данные и не должна использоваться как шаблон для production-развёртывания.
